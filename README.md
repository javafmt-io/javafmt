# javafmt

[![Quality gate status](https://sonarcloud.io/api/project_badges/measure?project=javafmt-io_javafmt&metric=alert_status)](https://sonarcloud.io/summary/new_code?id=javafmt-io_javafmt)

## Prerequisites

JDK and Gradle versions are pinned in `.sdkmanrc` via [SDKMAN!](https://sdkman.io/). There's no Gradle wrapper checked in — SDKMAN is doing that job.

```bash
# One-time SDKMAN install — see https://sdkman.io/install
curl -s "https://get.sdkman.io" | bash

# From the repo root:
sdk env install
sdk env
```

Set `sdkman_auto_env=true` in `~/.sdkman/etc/config` and `sdk env` runs every time you `cd` in.

## Build

```bash
gradle build
```

Everything goes through Gradle, including the VS Code extension's TypeScript compile. Don't reach for `npm` or `mvn` directly.

## Modules

| Module                  | What it does                                                                |
|-------------------------|-----------------------------------------------------------------------------|
| `javafmt-core`          | The parser and formatter. The only runtime dep is `slf4j-api`.              |
| `javafmt-daemon`        | `daemon.proto` and the `javafmt --daemon` server the CLI delegates to.      |
| `javafmt-cli`           | Standalone CLI. Ships as a fat JAR plus GraalVM native binaries per OS.     |
| `javafmt-spotless`      | A `FormatterStep` so any Gradle project on Spotless can pick it up.         |
| `javafmt-maven-plugin`  | Maven plugin (`javafmt:format`, `javafmt:check`). Built by Gradle.          |
| `javafmt-gradle-plugin` | Gradle plugin (`javafmtFormat`, `javafmtCheck`), plugin id `io.javafmt`.    |
| `javafmt-intellij`      | IntelliJ plugin. Drives `Reformat Code` through a warm `javafmt --daemon`.  |
| `javafmt-vscode`        | VS Code extension. Talks protobuf to a warm `javafmt --daemon` process.     |

The Maven plugin's JAR and `plugin.xml` descriptor are generated by Gradle via `org.gradlex.maven-plugin-development` — no `mvn install` step to bootstrap.

### The Gradle plugin needs Gradle 9.1 and a Java 25

`io.javafmt` needs Gradle 9.1 or newer, the first release that supports Java 25 toolchains. The plugin declares 9.1 as its minimum plugin API version, and its functional tests run against 9.1 as well as the current release. Unformatted files, javafmt errors and warnings are reported through Gradle's Problems API, so they show up in the build output, the problems report and IDEs that read it. The plugin loads in any Gradle daemon JVM, but javafmt itself runs in a worker process on a Java 25 toolchain. If Gradle can't find one, `javafmtCheck` and `javafmtFormat` fail and say so. Either install a JDK 25, or let Gradle download one by adding the Foojay resolver to the `plugins` block of `settings.gradle.kts`. The error message names the exact line to add, with the resolver version the plugin was tested against:

```kotlin
plugins {
    id("org.gradle.toolchains.foojay-resolver-convention") version "<version from the error message>"
}
```

### Excluding sources from the Gradle plugin

`javafmt { excludes = [...] }` takes Ant-style patterns, and every pattern is matched against the source file's path relative to the project directory, such as `src/main/java/gen/**` or `**/Generated*.java`. A source directory outside the project directory is matched the same way, so its paths start with `../`.
